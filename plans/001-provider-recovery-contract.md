# Provider recovery ownership

The existing ProviderRecovery owns one captured profile/provider workflow and
retains its connection until admitted receipt/readback work drains. Views render
copied scalar observations and forward choice/confirmation/navigation through
required typed callbacks. The owner decides eligibility, candidate identity,
consent sequencing, source revalidation, file inspection/deletion and outcomes.
A separate inspection fact prevents dialog waiting from masquerading as file I/O.

ProviderConsole checks exact captured admission adjacent to both ready input and
final mutation confirmation. Retirement rejects unsent work; physically admitted
work drains once without replay or publication to retired routes. The route
composition module captures actual profile dependencies without importing the
inventory page back into itself. Standard cycle checking protects this boundary.

Stock Hermes does not offer atomic expected-version credential/file mutations.
Existing source/file revalidation is preserved; subsequent remote changes remain
a stock contract limit. Client-only work targets the inspected unmodified API.

Existing owner, actual route, console and real transport controls cover behavior.
The small view dependency guard and23 exact retired identities prevent removed
raw UI policy from returning. Both PR/release workflows enforce the guard.
Native/device, rendered design and final whole-program gates remain open.

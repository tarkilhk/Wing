# Workspace voice admission

Existing recorder/playback owners coordinate captured immutable chat target and
generation across held arbitration. Workspace owns dictation eligibility, stock
remote factory and reply identity. VoiceDraft contains plain text/selection facts;
ComposerSession issues an opaque owner plus exact text revision capture. Admitted
application draft changes revoke that capture even when text returns to its old
value. Completion validates synchronously before persistence yields; UI applies
only admitted cursor/result. Keyboard editing remains disabled during recording.

The small workspace_voice_view_dependencies command rejects raw remote speech
namespaces in the completed workspace view. Existing public-owner-state checks
seven private authoritative voice facts; exact retirement protects six removed
declarations. Actual original source fails the namespace/retirement gates; the
original output owner fails three public-writer checks. Original recorder widgets
ancestry is outside that deliberately bounded field checker and fails INPUT, not
a false clean result. Dynamic finite fixtures protect all seven current fields.

Focused controls preserve capture/stop/cancel, native errors, draft/cursor insertion,
read-aloud toggle, exact captured owner and held recorder/playback retirement. The
original widget implementation overwrites a draft changed away and back through
the real application command; the successor rejects it and displays its outcome.
Final matched native/device/performance and rendered acceptance remain open.

Application startup is a separate typed composition function: acquire preferences
once, await existing connection recovery, construct existing preferences owner,
return those dependencies. Main retains Flutter binding, native intent startup and
runApp. No raw store escapes to the rendering library; existing low-level guard
protects the removed baseline without a new duplicated rule.

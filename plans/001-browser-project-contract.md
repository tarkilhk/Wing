# Browser and captured project actions

ChatBrowserData owns one profile read page and private wire rows, copied readonly
scalar list/project/workspace facts, paging, discovery, search, retry, arrangement
and menu issuance. BrowserActionSession borrows the captured canonical resource
and owns eligibility, permanent scope revocation, duplicate submission, errors and
outcomes. It adds no second cache or journal. ProfileWorkspaceController remains
the canonical session/project/runtime/draft writer.

Browser, row and project views render typed facts, collect transient choices,
perform clipboard/navigation work and forward intent. Physical gateway RPC and
owned dashboard PATCH/DELETE require captured admission immediately after held
connect/auth and before offering a write. Already admitted uncertain writes retain
the original receipt and are never replayed. Latest stock has no atomic remote
profile/project revision precondition; local admission does not create one.

Browser retirement revokes every issued action, including an idle modal, while
the menu route remains responsible for disposing its observation. This preserves
Profile changed feedback and denies a captured menu after A-to-B-to-A navigation.
Full refresh resets arrangement inside the final existing publication, preserving
the bounded start/profile/finish notification count. Failed-only recovery retains
healthy identity/order. Workspace shutdown preserves a prepared delete receipt;
a live workspace may retire a known-unsent receipt, but a closed one starts no
new retirement write. Draft/quarantine/no-server-write assertions remain intact.

Four small commands protect browser/view, row/view, project/view dependencies and
finite final scalar DTO/readonly collection boundaries. Exact retirement protects
46 removed identities. Original source fails all five checks. Existing captured
menu, held authentication, pending read, scope switching, no replay, paging,
project mutation, ordering and durable cleanup controls verify temporal behavior.
Whole-source/native/render/device/program acceptance is separate and remains open.

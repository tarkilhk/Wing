# ARCH_PROFILE_IDENTITY_VIEW

The completed `admin_identity_page.dart` library, including its actual parts,
accepts a supplied session factory, renders immutable facts/enums and delegates
commands. It cannot reference canonical transport/profile/administration/managed
file authorities, identity intent/observation/result policy, metadata codecs, or
construct/capture a new identity session. Its captured administration authority
is private; typed context remains on the passive state.

```sh
dart run tools/architecture/rules/profile_identity_view.dart --json
dart run tools/architecture/tests/profile_identity_view_test.dart
```

The rule matches resolved declaration provenance, not variable spelling. It
covers constructor/type references (including implicit superclass construction),
methods and captures, inferred getter return values, aliases, barrels, show/hide combinators, inherited operations, cascades
and definition parts. The six named application modules are canonical locations;
`connection_manager.dart` selects only DashboardClient. The identity model selects
intent/observation/resolution/result and normalization/validation APIs; its field
enum remains legitimate rendering input. Canonical dart:convert, YAML and File
metadata APIs are forbidden; unrelated names and ordinary presentation maps are
valid. This is one finite completed-view owner boundary.

The parsed prefilter derives complete declaration/member vocabulary from the
canonical app modules, Dart conversion library, YAML package and the two File authority declarations
(including exports and parts), then follows authored aliases. Canonical enum constants,
function typedefs, mixins and extension types are included. Potential matches are
resolved; a coincidentally named passive field cannot establish a violation.
Unknown inherited or indirect receivers remain candidates. A finite clean-path
proof accepts uniquely imported canonical passive enum constants, explicitly
typed session/model facts and fields, and declared borrowed session commands
whose return annotations resolve to passive facts, core scalars or Future of
those facts. It follows only declared passive field chains and a direct declared
session command result; aliases, generic substitutions and inferred custom
getters are not certified. Lexical/formal/type-parameter/pattern/loop/catch
shadows, imported core-looking annotation homonyms and raw-return members fall
back to semantic resolution. Novel public owner/DTO members remain in the full
candidate vocabulary. A borrowed-session type is accepted by actual canonical
declaration identity; an authority typedef using the same session spelling is
a permanent bad fixture, with an original actual false-zero CLI reproduction.

Two specific presentation patterns also use parsed declaration proofs: an own
final controller initialized by the direct imported Flutter
TextEditingController constructor may access text/dispose, and a State of the
actual authored widget may invoke its declared session factory or call the
framework superclass dispose. Authored namespace homonyms and mixin uncertainty
prevent these shortcuts. Namespace show/hide and prefixes remain significant;
the ordinary SDK analyzer owns external namespace ambiguity and semantic
validity. This is not an expression typechecker or an exemption based on variable
spelling. All other potential matches are resolved.

Bodies and inference inputs
are never replaced. Selected syntax, graph/actual part ownership, configuration,
authored namespace presence and SDK provenance are validated unconditionally.
Namespace traversal follows actual package/relative/file URIs, so an in-scope
file-URI intermediary cannot conceal an unrepresented actual part.
Conditional imports/exports in the dependency closure, file-addressed parts the
shared snapshot cannot represent, and authored aliases outside parsed lib require
an additional proof and return input status 2. Candidate semantic errors are
never ignored. The first three independent review counterexamples (canonical
enum, unrepresented actual part, JsonUtf8Encoder) are permanent fixtures.

An empty-candidate result proves this finite property, rather than unrelated
semantic correctness: the mandatory ordinary SDK analyzer still owns noncandidate
semantic errors and ambiguities, including an unrelated error in an otherwise
passive-only view. Both noncandidate fixtures prove guard 0 alongside an actual
nonzero standard-SDK analyzer result; raw candidate errors still return 2. API fixtures and actual CLI proofs exercise bad
1, valid 0, malformed/provenance input 2 and invalid SDK 2, including freshly
compiled execution. The host wrapper runs fixtures and actual production; parent
acceptance wires its independent command into required offline CI and measures
feedback on a fixed checkout. Correctness runs under concurrent work establish
no quiet timing budget.

The optimized 90-case successor passed quiet whole-checkout feedback on the same
fixed source and SDK. Its local budgets are **12 seconds for a source command**
and **0.5 seconds for a compiled command**, including first process startup.
Acceptance measures the first process and three subsequent new processes; CI
scheduler timing remains informational. Source/input/binary hashes, host details
and recorded measurements remain in private evidence. The compiled clean path
does not resolve unrelated semantics; the mandatory SDK check and the actual
candidate/input fixtures retain the division documented above.

This rule cannot prove arbitrary locally invented string/map business behavior,
profile metadata integrity, same-name identity continuity, dispatch lifetime,
preflight atomicity, partial ACK or uncertainty. Those remain controlled public
owner/repository/widget regressions and review obligations. Stock metadata has no
revision/CAS; forbidden YAML and raw transport access cannot turn a client check
into an atomic server transaction. Notification retirement needs actual reentrant
listener tests, rather than a blanket asynchronous-code lint.

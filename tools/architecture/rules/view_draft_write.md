# ARCH_VIEW_DRAFT_WRITE semantic SDK contract

This independent rule checks view/presentation roles. Its finite property is canonical ProfileChat.draft setter operations; not persistence ordering. Syntax selects candidates; resolved canonical library/declaration identity decides findings. Existing fixtures cover the applicable aliases, barrels, parts, cascades and valid unrelated symbols. Dynamic candidate operations and unproved conditional dependencies return input exit 2. Runtime races remain behavioral-test properties.

The mandatory complete-scope architecture aggregate enforces production scope. The pure fixture runner proves resolver behavior separately; a clean zero-candidate production run cannot prove resolution.

```sh
dart run tools/architecture/rules/view_draft_write.dart --json
dart compile exe tools/architecture/rules/view_draft_write.dart -o build/view_draft_write
dart run tools/architecture/tests/view_draft_write_test.dart --compiled build/view_draft_write
```

Source and compiled runners use the existing shared `tools/architecture/dart_sdk.dart`. An explicit `--sdk PATH` is validated before the no-candidate shortcut; invalid SDK input exits 2. Standalone compiled fixtures outside a configured Flutter checkout receive the real SDK explicitly. The public proof runner checks source and freshly compiled invalid (1), valid (0) and unverifiable (2) CLI cases with exact diagnostic ID/file/line, and an invalid explicit SDK on a valid no-candidate fixture. SDK failure cannot count as the intended violation proof.

Keep source/helper/SDK/binary hashes and repeated cold/warm process evidence under ignored `build/` or private acceptance storage. Complete-scope correctness and compiled semantic correctness are separate from feedback timing. Complete authored production scope passes fresh source and compiled checks. The local feedback budgets remain 15 seconds for a source process and 1 second for a compiled process on the recorded host/SDK; repeated quiet acceptance, source/SDK/binary hashes and scope are stored privately. Compare regressions under the same conditions and optimize a repeated breach rather than raising these budgets. No timing observation changes deterministic exit status.

# Captured operation ownership

`AdministrationOperationSession` is the sole polling writer for one captured connection, stock action name and PID. `AdministrationHealth` retains the Doctor and security-audit trackers and derives its observations and unchanged persistence codec from them. Result pages borrow those same trackers; opening or closing a diagnostic result route does not start another polling loop. Generic skills, setup and speech compositions own their route tracker and dispose it in a `finally` after navigation.

The tracker holds a connection lease throughout its lifetime and each admitted read holds a draining lease. Retirement immediately revokes publication and further polling; notifier storage is released after a synchronous notification unwinds. An in-flight read may settle without publishing to a retired owner. Disposal ends observation; it does not stop the server process. Concurrent manual and scheduled refreshes join the same admitted read. PID replacement or malformed status retains the last confirmed output and timestamp with an error. A transient read failure retries the same captured run; it never POSTs another run.

Diagnostic admission is typed by `AdministrationDiagnostic`. The repository uses the existing connection-owned mutation seam, which checks captured authority immediately before HTTP dispatch after authentication. Only failures proven to precede delivery may retry while admission remains active. Timeouts, connection resets and rejected replies do not replay a diagnostic. Receipts require stock `ok:true`, name and integer PID. Retiring Health revokes a held-authentication start before dispatch; admitted work keeps its connection until it settles.

Immutable observations own decoding, output, completion and diagnostic classification. Security-audit exit 1 is a findings outcome only with a verified report; unavailable summaries remain unavailable. `AdminActionPage` renders typed facts and forwards refresh/Ask Hermes commands. It does not retain a raw repository, wire status map or mutable chat. `DoctorFindingDraftSession` captures the workspace before preparing a durable unsent draft; only immutable draft key and prompt are retained for navigation retries. Initial current-route admission and route/operation lifetime fence draft preparation. Route or operation retirement blocks later navigation, while an already admitted draft creation may settle as a saved draft.

Logs were moved to `admin_logs_page.dart`; that existing workflow remains mixed and is not claimed as migrated. Skill, tool and speech mutations also remain separately inventoried; only their common result lifecycle is migrated here.

## Prevention

The existing `ARCH_RETIRED_DECLARATION` guard records 28 exact retired identities in `tools/architecture/dead_code/retired.json`: the old repository action and Health observation definitions, Health's duplicate polling/storage and public observation mutators, the result view's raw dependencies/polling/prepared-chat state, and the UI diagnostic-start helpers. It checks canonical containing libraries, including actual parts, and permits moved immutable identities, owner delegation and unrelated same-name declarations. `test/retired_declarations_guard_test.dart` adds three focused invalid cases and one nearby valid case through the existing parsed rule API; its existing independent CLI proof remains unchanged. Run the focused test with `flutter test test/retired_declarations_guard_test.dart` and the production guard with `dart run tools/architecture/dead_code/retired_declarations.dart --strict`.

This declaration guard prevents those exact APIs from returning. It cannot detect a renamed duplicate poller, prove that arbitrary callbacks obey single-writer ownership, or establish dispatch/retirement safety. Those behavior properties belong to the retained operation, draft-retirement and held-authentication regressions; this guard makes no claim that all administration business logic has left the UI.

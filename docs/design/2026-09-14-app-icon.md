# Playful app icon and messenger wing

The owner selected **03 · Playful** from the [expression comparison](images/icon-expression-selection.png), then approved production and Android integration. Earlier caduceus and portrait alternatives are unselected. The selected portrait has a wink, a simple dark bob, mint headphones and a three-part messenger wing on the visible earcup.

## Identity

- Normal launcher: Playful portrait on navy.
- Notifications and status bar: the white messenger wing on transparency. Android supplies the displayed tint.
- Optional Android themed launcher icons: the same wing, with system-supplied colors.
- Brand palette: navy matte `#0C304A`, cream `#FFF9EB`, mint `#C6EED5`. The generated raster has minor color variation and antialiasing. These are identity colors, not new screen-theme tokens.

Keep the portrait's simple hair shapes and wink. Do not introduce a facial illustration in the status bar. The small wing is a vector adaptation of the earcup emblem with wider gaps for small sizes.

## Production assets

| File | Purpose |
| --- | --- |
| [playful-master.png](../../assets/icon/playful-master.png) | Standalone production portrait with navy matte; retain as the source for exports. |
| [wing.svg](../../assets/icon/wing.svg) | Canonical scalable notification and themed-icon wing. |
| [icon.png](../../assets/icon/icon.png) | 1024 px full-bleed launcher/store composition. |
| [generate-app-icons.cjs](../../scripts/generate-app-icons.cjs) | Reproducible density, store and native vector exports. Requires Node.js and `sharp`. |
| [production prompts](2026-09-14-app-icon-prompts.md) | Exact built-in ImageGen prompts and reference provenance. |

Run `node scripts/generate-app-icons.cjs` with `sharp` available to Node, through a local installation or `NODE_PATH`. The generator uses the checked-in master and SVG; it does not regenerate artwork or call a remote service.

The adaptive layers are 108 dp. The source portrait occupies about 62 dp after padding; the central 72 dp viewport supplies the corresponding legacy and store composition. The foreground raster includes its navy matte. It has no baked-in rounded tile or shadow. Android applies its own mask. Legacy PNGs have rounded corners. See [Android's adaptive-icon requirements](https://developer.android.com/develop/ui/compose/system/icon_design_adaptive).

The `ic_stat_hermes` vector is a 24 dp white alpha mark. `PluginTurnNotificationSink` selects it by drawable name. `res/raw/keep.xml` retains it during optimized resource shrinking. API 33 resources add the wing monochrome layer; API 26 resources keep the regular portrait. Round and ordinary adaptive resources use the same foreground. Launcher shortcuts inherit the new app icon.

## Validation

- All 27 existing tests passed in `plugin_turn_notification_sink_test.dart`, `turn_notification_service_test.dart` and `android_launcher_shortcut_contract_test.dart`.
- `flutter build apk --debug --target-platform android-x64` succeeded. AAPT2 confirmed that the APK contains `ic_stat_hermes` and `ic_launcher_monochrome`.
- The [production proof](images/icon-production-proof.png) is rendered locally from the shipped assets. It checks circle and rounded masks, the 48 px legacy launcher, and the wing at 18 and 24 px against light and dark backgrounds. The portrait's outer hair/shoulder may meet the circular edge; the wink and earcup emblem remain visible.
- Installed the debug APK on the existing `emulator-5556` QA device. The [app drawer](images/icon-emulator-launcher.png) displays Playful. The built-in **Enable and test notifications** action posted a real local notification after granting Android permission. Its resource ID `0x7f07007c` resolves to `ic_stat_hermes` in this build. The [notification shade](images/icon-emulator-notification.png) and [home-screen status bar](images/icon-emulator-status-bar.png) display the wing. The colored dot and suggested-app ring are launcher decorations.
- The optional themed launcher layer is packaged and rendered in the asset proof; switching the emulator's wallpaper-themed icon setting was not part of this check. Optimized release shrinking was not exercised by the debug build.

Changes and artifacts belong to this task's OneDrive checkout. No personal phone installation or release publication was performed. The debug APK is an x86_64 emulator build, not the ARM64 personal release.

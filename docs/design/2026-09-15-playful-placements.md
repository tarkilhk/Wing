## Implementation and rendered review

All five placements use `PlayfulPortrait`, backed by the approved `assets/icon/icon.png` export. The widget excludes decorative image semantics because nearby text supplies the name. It sizes the decoded image for the device pixel ratio. Drawer scope text can wrap, and the portrait keeps the same palette for every accent family.

The empty greeting stays in the existing reverse transcript scroll view. This preserves its controller and history behavior when messages arrive. Loading, errors, pending history, streaming, busy state and visible activity suppress the greeting.

The transcript, installed-version, app-navigation and Studio layout suites passed all 79 checks. Added checks cover empty-to-message and history-state transitions, plus a short scrollable transcript. The rendered review also checks first-connection controls at 320 dp with 200% text in both themes. Existing Studio checks cover all five accent families, narrow and wide layouts, enlarged text, the composer, drawer and settings.

The focused render run passed all 10 checks, including the two new first-connection cases. `flutter analyze --no-pub` reported no issues.

## Personal 2.36.8 release preparation

The owner requested committing and pushing to main, then updating their phone. The release uses version `2.36.8+2225`, with effective ARM64 Android code `22252` and the existing Personal signing identity.

The full suite completed with 1,629 passes, 10 environment-dependent skips and five failures. Two image tests needed to scope their no-image assertion to remote message content, the release identity test needed the new version, and two first-connection tests needed to scroll until their lazily built target appeared with the test font. After these corrections, all 62 checks across the four affected suites passed. The initial focused portrait and navigation checks also passed as recorded above.

Static analysis reported no issues. The dependency review found available upgrades; this UI release keeps the existing lockfile. Architecture, error/loading behavior and shared state lifecycles are preserved. The existing local image is the only newly bundled asset. No network behavior or credentials changed. Phone-sized, wide, light/dark and enlarged-text layouts were checked. Live gateway send/stream smoke tests were not repeated for this portrait-only update. Signed build and installation evidence will follow after completion.

## Reading the mockups

These are raster previews generated by the built-in ImageGen tool. Text and geometry are illustrative, not measurements or evidence that an interaction is implemented. The boards use 2.36.6 and Home / Personal as sample app metadata and scope.

For implementation, retain existing navigation icons, accent/theme selection controls, notification settings, composer actions and Activity layout. The dark board's dropdown-like Theme/Text size controls, the decorative badge outlines, extra timestamp treatment and the floating button glimpsed behind the drawer are generation artifacts, not proposed behavior or layout changes. Keep the current author's text alignment and the context ring beside the model selector. Do not add the obsolete context fuse shown in an older reference board. The portrait must load from the approved local asset, not be recreated separately per widget.

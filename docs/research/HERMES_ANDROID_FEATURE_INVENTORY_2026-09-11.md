# Hermes Android feature inventory

Source audit dated 2026-09-11. Android checkout `b8f1d981a272059076cefce179e2de9596dc9e06`. The initial `git status --short` was empty. Git printed a permission warning about the user's global ignore file. The package declares `2.1.1+2144` in [pubspec.yaml](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/pubspec.yaml#L1). This report describes the checked-out source, not an installed APK or a claim that every backend contract has been tested live today.

## The distinction that changes the comparison

The production entry point now opens **ProfileWorkspaceScreen** for every saved connection. It does not open the older `WorkspaceScreen` and `ChatScreen`. Notification taps also open the profile workspace. Those older screens still contain substantial implementations, tests and documentation, but they are not reachable through the normal current navigation graph. Count them as reusable work, not delivered mobile features. See [main.dart](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/main.dart#L109), [connection navigation](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/main.dart#L442), and the [profile workspace imports and navigation](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/core/screens/profile_workspace_screen.dart#L1).

This is especially consequential for voice, Cron, Memory, Files, Settings, export/share, rich tool events, and the older Home/Activity/More shell. Their classes exist. The active profile workspace does not route to them. The old routes are in [WorkspaceScreen](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/core/screens/workspace_screen.dart#L1188) and [SessionListScreen](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/core/screens/session_list_screen.dart#L890), which themselves have no route from current `main.dart`.

In the tables, **Active** means implemented and reachable through the current app. **Partial** means a narrower active implementation or a backend dependency that matters. **Retained** means implemented in an older, currently unreachable screen. **Absent** means no implementation was found in the active application path. A slash command can provide an advanced alternative without constituting a dedicated mobile screen.

## Reliability, privacy and backend dependencies

The current application has a strong ownership model. A chat key includes saved connection ID, an authenticated connection identity, profile and durable session ID. ProfileGateway puts `profile` in REST/RPC requests and validates owners in responses. Credential changes create a new controller identity instead of retargeting an existing socket or pending notification. [chat keys](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/core/services/profile_workspace_controller.dart#L21), [scoped requests](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/core/services/profile_gateway.dart#L205), [registry](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/core/services/profile_workspace_registry.dart#L15), [identity](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/core/services/profile_connection_identity.dart#L10).

Credentials live in platform secure storage, while connection metadata lives in shared preferences. Legacy secret migration includes failure handling. Android system backup is disabled; cleartext traffic remains permitted to support HTTP/private LAN hosts. This is configurable HTTP/HTTPS access, not enforced transport encryption. [credential storage](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/core/services/connection_manager.dart#L21), [migration](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/core/services/connection_manager.dart#L170), [manifest](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/android/app/src/main/AndroidManifest.xml#L6).

The active recovery scheme persists pending chat **identities**, not prompts, transcript text or paths. It reconnects with bounded backoff, resumes the server session, reads server history and does not resend uncertain prompts. Process restart restores pending owners where available. Unsent drafts, transcript cache, completed activity and scroll offsets are chiefly in memory; this is not a full offline client or durable outbox. [reconnect](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/core/services/profile_workspace_controller.dart#L2144), [journal](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/core/services/profile_workspace_controller.dart#L2241), [draft state](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/core/services/profile_workspace_controller.dart#L70), [uncertain submit](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/core/services/profile_workspace_controller.dart#L1947).

The older recovery coordinator/turn journal implements a separate advertised durable contract with legacy fallback. Its presence and README description must not be used to assert that the new profile route has exactly-once submission/recovery. Current profile code explicitly uses conservative no-resend and server reconciliation. [old recovery](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/core/services/gateway_turn_recovery.dart#L1), [active prompt](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/core/services/profile_workspace_controller.dart#L1885).

The active client depends on a modern dashboard with profiles and paginated session/history REST, a working authenticated desktop gateway, ownership metadata, projects RPCs for project features, search endpoint for content search, and command catalog/dispatch for commands. Its profile repository has no legacy fallback. The client checks safety-sensitive ownership, but comments document limits in stock server live-session contracts and a profile deletion race. Do not reconnect old management screens without adding equivalent profile scoping. [discovery](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/core/services/profiles_repository.dart#L53), [gateway contract](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/core/services/profile_gateway.dart#L205), [move safety](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/core/services/profile_gateway.dart#L519).

No native offline transcript store/outbox, biometric app lock, certificate-pinning UI, push messaging service, notification inline reply, Android widget, hardware-keyboard command palette, native kanban board or complete audit/log console was found in the active route. These are source-audit observations rather than proof that no optional backend command can achieve part of the same outcome. The complete active UI is concentrated in [ProfileWorkspaceScreen](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/core/screens/profile_workspace_screen.dart#L22), [ProfileWorkspaceBrowser](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/core/screens/profile_workspace_browser.dart#L17), [ProfileMessage](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/core/widgets/profile_message.dart#L12), [main.dart](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/main.dart#L1) and [AndroidManifest.xml](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/android/app/src/main/AndroidManifest.xml#L1).

## Documentation discrepancies and planning implications

1. README identifies v2.1.0/build 2140 while package source is v2.1.1/build 2144. More seriously, it presents the former Workspace/More navigation, native voice, rich event handling, exports and 72-hour quick-chat lifecycle as current capabilities. Current entry-point routing does not expose those implementations. [README](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/README.md#L1), [pubspec](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/pubspec.yaml#L1), [current route](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/main.dart#L442).
2. README's on-device/full-text/AI search mode description belongs to the former browser. The active browser uses server content/ID search plus loaded title matches and exposes its 100-result cap. [README](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/README.md#L73), [active search](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/core/screens/profile_workspace_browser.dart#L367).
3. Claims of multi-attachment support are broadly true at the draft/service level, but active acquisition is one FilePicker result per invocation and active draft UI lacks the older thumbnails/reorder/retry controls. [active picker](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/core/screens/profile_workspace_screen.dart#L491), [service limits](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/core/services/attachment_draft_service.dart#L290).
4. Runtime theme/text-size support survives the navigation change, but the settings controls do not. Restore survives through HomeScreen; export remains behind the old SettingsScreen. [main theme](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/main.dart#L197), [restore](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/main.dart#L330), [old settings](https://github.com/tarkilhk/hermes-android/blob/b8f1d981a272059076cefce179e2de9596dc9e06/lib/core/screens/settings_screen.dart#L321).
5. Active profile switching, ownership checks, answer branches/versions, paginated history, shared server organization and command dispatch are substantial delivered improvements that older high-level docs can understate. Preserve those while integrating useful retained features, rather than restoring old screens wholesale.

For a mobile backlog, the strongest near-term work is to connect existing useful implementations to the profile-owned architecture: voice/dictation and camera capture, output export/share/download, a profile-scoped attention inbox with complete blocking-request handling, reachable device settings, and selected Cron/memory/skills workflows. Reliable delivery under Android lifecycle constraints and an honest connection/support diagnostic are more important than reproducing desktop file trees or terminal controls. These are product recommendations from the source audit, not implementation claims.

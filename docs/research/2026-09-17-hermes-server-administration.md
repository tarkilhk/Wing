The live GitHub commits API was queried before downloading that exact commit's source archive. Local older backend checkouts were not treated as the target. [Inspected commit](https://github.com/NousResearch/hermes-agent/commit/36842e639a178741b70c821e0f4cdd129cd0dfe3).

Scope: research only. No UI changes, deployed-server changes, live administration requests, credential inspection, or upstream patches. Sources below are pinned to the inspected commit. API statements describe stock source support, not a live deployment test.

## Finding

**Updates are not the only real server operation.** Whole-install backup/export, gateway process control, and host resource monitoring are concrete omissions in Wing. Managed local inference is another substantial machine-level capability. However, most of these are actions or status views, not settings, and some advanced server settings are stored in the configuration of the profile that launched the process.

Three scopes must stay distinct:

1. **Installation/machine:** the shared checkout, all-profile backup root, shared local model downloads/runtime.
2. **Running service/process:** listener access, authentication gate, gateway lifecycle, process resource limits. These can affect several profiles but do not necessarily affect every Hermes process on the machine.
3. **Profile:** model credentials, defaults, messaging identities and pairing, webhook subscriptions, tool/agent configuration and most data stores.

An endpoint without a `profile` parameter does not establish machine ownership. For example, webhook subscriptions use the current Hermes home, whereas backup explicitly climbs to the installation root. [Webhook owner](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/webhook.py#L21-L47), [backup owner](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/backup.py#L665-L691).

### Backup/export is the strongest missing server action

`run_backup()` explicitly uses `get_default_hermes_root()`, then recursively archives that root. Named profiles are inside it. This is broader than the dashboard's selected or launch profile. The stock API now supports creating an archive in its backup directory, observing completion through the background-action API, and downloading it to a remote client. There is no need for a custom endpoint or shell access merely to export a normal backup. [Backup traversal](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/backup.py#L277-L315), [backup root](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/backup.py#L665-L691), [API and download confinement](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/web_routers/ops.py#L516-L555), [action status](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/web_routers/actions.py#L329-L374).

This is a data backup, not a complete machine image: code, dependencies, caches and managed model/runtime downloads are excluded. Durable secrets such as `.env`, `auth.json` and the local vault are included, so the downloaded archive contains credentials. [Exclusions and secret files](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/backup.py#L46-L134).

Restore is available through `POST /api/ops/import` and multipart `POST /api/ops/import-upload`, but is **not automatically the inverse of the all-profile backup**: `run_import()` restores into `get_hermes_home()` of the process action. An isolated named-profile backend therefore has a different destination than the normal root backend. Neither import endpoint exposes a profile/target selector. Existing config requires overwrite consent through the `force` field because the child has no interactive stdin. Runtime-state files are preserved, and the importer has gateway revival behavior. Treat restoration as a separately scoped recovery action, not an assumed safe profile import. [Upload/import routes](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/web_routers/ops.py#L557-L602), [request consent field](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/web_models.py#L377-L384), [restore target and effects](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/backup.py#L969-L1029).

### Gateway control is genuine runtime administration, with topology caveats

The API does not mean “restart the entire machine” or invariably “restart only this profile.” For a profile served by the shared default multiplexer, restart is deliberately retargeted to that shared process. Its other served profiles are affected. Start/stop on such a profile are refused with HTTP 409 because no independent process belongs to that profile. Status exposes gateway topology and `gateway_shared_with` so a client can identify this impact. [Target selection](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/web_server_gateway.py#L496-L541), [topology](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/web_server_gateway.py#L145-L201), [shared impact field](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/web_routers/status.py#L319-L326).

Operations spawn the real CLI, and success of the initial HTTP call means the action started, not that the gateway is healthy again. System-scope services need root; the backend checks noninteractive sudo and refuses with host-side remediation if unavailable. A separated container/runtime may be observable without being controllable by this backend. [Action spawning and system-service limits](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/web_server_gateway.py#L443-L490), [cross-container health probing](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/web_server_gateway.py#L22-L40).

Drain/cancel writes the control marker for the current home; it is an operational facility, not an arbitrary machine fleet API. The gateway watcher owns the actual transition. Gateway migration plan/apply APIs also exist, but are topology migration tooling rather than recurring settings. [Drain endpoint](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/web_routers/actions.py#L146-L207), [marker home](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/gateway/drain_control.py#L59-L81).

Deployment-dependent reachability matters: the source explicitly handles dashboards embedded inside the gateway process. **Inference:** stopping or restarting that owning gateway can disconnect the administration API itself; after stopping it, the same API cannot necessarily start it again. Recovery depends on the host's service manager or a separately running backend. This needs to be established before offering a generic Stop button. [Embedded-process handling](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/web_server_gateway.py#L387-L396).

Do not confuse this with a dashboard restart button. The inspected routes have no general remote dashboard stop/restart endpoint. `hermes dashboard/serve --stop` is a host CLI operation. New `POST /api/health/retirement` is cooperative Desktop process retirement: prepare/commit/cancel an admission fence after idle proof, not a general restart or shutdown operation. [CLI lifecycle flags](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/subcommands/dashboard.py#L39-L45), [retirement route](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/web_routers/status.py#L120-L145), [fence implementation](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/backend_retirement.py#L1).

### Shared local inference is real but mixes machine and profile effects

Upstream explicitly makes engine binaries, presets, server state and GGUF model files machine-scoped under the default root. Endpoints can inspect hardware, install/update the runtime, download or delete models, start/stop the local server and unload models from GPU memory. [Runtime root](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/local_runtime/binaries.py#L56-L63), [model directory](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/local_runtime/bootstrap.py#L44-L55), [install/download/delete API](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/web_routers/local_models.py#L647-L713), [server/eject API](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/web_routers/local_models.py#L779-L835).

However, `local_runtime.enabled` and the default selected model remain profile config. Start/stop writes the launching profile's enabled flag; activate/quickstart also selects its model. These handlers have no profile parameter. Stop may return 409 when another live Hermes process owns the runtime. Therefore it would be misleading to label every local-model operation “server-only” or promise that toggling one profile disables all future starts by other profiles. [Profile config writes](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/web_routers/local_models.py#L194-L212), [default assignment](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/web_routers/local_models.py#L275-L279), [ownership refusal and activation](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/web_routers/local_models.py#L779-L858).

## Real server settings with incomplete remote administration support

**Server login and network exposure:** bind address/port; dashboard public URL; trusted reverse proxies; password username/hash and signing secret; login session lifetime; dashboard OAuth registration. These govern who can reach or authenticate to the service and are separate from a profile's model-provider OAuth. The auth registry explicitly supports host-owned providers that outlive per-profile plugin managers. Public host trust and auth-gate state are resolved into process state at startup. [Settings](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/config_defaults.py#L944-L998), [host-owned auth registration](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/dashboard_auth/registry.py#L106-L116), [startup gate](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/web_server.py#L1093-L1138).

Persistence still comes from environment and launch-profile config. Generic `PUT /api/config` can save nested dashboard settings, but its save hook broadcasts approval changes, not listener/auth reconfiguration. Password-provider rediscovery can replace a registration internally, yet the stock auth routes are login/logout/refresh/identity/tickets, not a supported password-rotation, active-device listing, global logout or listener-management flow. Do not claim these settings cannot be written at all; the limitation is a dedicated, reliable remote apply/recovery workflow. Host/port still require the launch invocation; OAuth registration has a host CLI command. [Password settings resolution](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/plugins/dashboard_auth/basic/__init__.py#L187-L263), [config save](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/web_routers/config_env.py#L113-L150), [auth routes](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/dashboard_auth/routes.py#L176-L506), [registration CLI](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/subcommands/dashboard.py#L102-L125).

**Process tuning:** e.g. `runtime.nofile_soft_limit`, and dashboard WebSocket/proxy configuration. These have real process effects but are persisted in profile configuration; the nofile limit is applied when server/CLI startup runs. They are advanced deployment/runtime settings, not evidence of an independent global configuration store. [Resource-limit implementation](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/resource_limits.py#L22-L79), [server startup](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/web_server.py#L1390-L1407).

## Things that should not be counted as new global server settings

- **Profiles themselves:** managing the collection is useful elsewhere; it does not make a profile's provider or other config server-owned.
- **Session concurrency limits:** `max_concurrent_sessions` is resource policy against the owning profile's active-session registry, shared across that profile's CLI/dashboard/messaging surfaces. The default registry path uses `get_hermes_home()`, so “global active session cap” in a defaults comment does not mean a universal server cap across profiles. [Registry home](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/active_sessions.py#L166-L171), [scope contract](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/active_sessions.py#L435-L448).
- **Messaging pairing:** `/api/pairing`, approve/revoke/clear-pending explicitly support a profile and use its pairing store. These are messaging-user approvals, not an inventory of phones logged into Wing. [Pairing ownership](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/web_routers/ops.py#L57-L120).
- **Webhooks:** routes/config use the launch profile's home even though `/api/webhooks` is unscoped. Enabling may restart a shared gateway, but that side effect does not change subscription ownership. [Subscription/config owner](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/webhook.py#L21-L54), [enable/restart](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/web_routers/ops.py#L145-L172).
- **User plugins:** installation storage is `get_hermes_home()/plugins`, and enable/provider choices use config. Unscoped dashboard endpoints do not make all plugins a machine-wide preference. [Plugin directory](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/plugins_cmd.py#L172-L176), [plugin routes](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/web_routers/dashboard_ui.py#L197-L270).
- **Outbound egress proxy:** `GET /api/egress/status` is a missing operational status surface, but config, binary and proxy state are tied to the current home. Install/setup/start/stop/restart/reload are CLI commands, not stock dashboard mutation endpoints. It is not proof of universal machine ownership. [Status route](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/web_routers/config_env.py#L105-L110), [state scope](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/agent/proxy_sources/iron_proxy.py#L159-L174), [CLI surface](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/proxy_cli.py#L21-L70).
- **Diagnostics:** doctor/security audit are existing Wing actions and logs are current-home data. `POST /api/ops/debug-share` additionally uploads reports/logs to a paste service; it is a support action, not a new setting or purely local export. [Diagnostics and upload](https://github.com/NousResearch/hermes-agent/blob/36842e639a178741b70c821e0f4cdd129cd0dfe3/hermes_cli/web_routers/status.py#L714-L765).

## Recommendation for the pending navigation decision

The code supports retaining a **small server-maintenance area**, but it does not establish that a dedicated Server tab is necessary. The meaningful near-term grouping is **updates, backup/export, gateway controls and host status**. These could live together in server details or a maintenance screen; placement is a separate design decision.

Backup/export is the clearest missed capability. Gateway control and host stats are the next useful candidates. Shared local-model management is genuinely server-side but materially expands Wing's present scope; it should not be added merely to fill a tab. Auth/network settings exist, but need careful treatment of launch scope and restart/recovery reachability before presenting them as normal editable mobile settings. No implementation is authorized or prescribed by this report.

Remaining uncertainty: source support is verified; no running server's service topology, privileges, install mode, resource capabilities, or authentication deployment has been probed. A “server” may represent one installation, several processes, or separated containers. The UI should not collapse those distinctions into a universal all-profile operation.

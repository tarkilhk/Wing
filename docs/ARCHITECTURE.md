# Wing architecture and ownership map

This is the maintained map of application owners and their interface boundaries.
Scope: this Wing checkout, current upstream unmodified Hermes, client-only changes.
The completed cleanup's acceptance record lives in [plans/README.md](../plans/README.md).
For feature work and ownership changes, follow
[maintain-feature-architecture](../tools/agent_skills/maintain-feature-architecture/SKILL.md).

## Find the owner before changing behavior

`tools/architecture/roles.json` assigns authored `lib/` Dart files their actual
role, feature and real Dart library. `profile_workspace_notifications.dart` and
other declared controller parts belong to their owning library. Use this map and
the live role/root manifests to locate current responsibilities.
`plans/001-feature-inventory.md` preserves the completed cleanup's hash-bound
review snapshot; its counts and hashes describe that revision. Imported
Foundation notifiers, Unicode helpers, rendering platform views and route leases
are classified by purpose; composition does not exempt a whole library.

For an integration change, inspect latest stock upstream and record its SHA first. A test fixture, sibling prototype or old deployed server is not the API specification. Use canonical `WorkspaceScope`/`ProfileSessionKey`; never silently change shared profile preferences to simulate an unsaved preview. Clean replacements update every caller and remove the old seam. Persisted format changes and any compatibility behavior require the user's explicit approval.

## Interface and direction contracts

The application flow is intent → owned command → immutable observation → rendering. ProfileWorkspaceController, ProfileWorkspaceData and ProfileChat retain private canonical storage and expose readonly observations and explicit commands. Published collections protect nested values; canonical discovery and rows retain their admitted identities. Extracted sessions borrow those facts instead of sharing mutable bags or creating a second writable cache. Actual runtime composition captures the canonical key/runtime identity; open/create owns registry installation. Use existing ChangeNotifier/Listenable and constructor injection. Small pure rules are functions/value types; I/O seams earn interfaces when production adapters and behavioral fakes differ.

ComposerDraftStore is the sole existing draft codec and ordered adapter; AttachmentDraftService owns file/upload work. Composer-issued submission tickets capture work and revisions; the workspace retains runtime admission and RPC authority. Automatic queue draining requires positively observed access and same-profile live availability, separate from optimistic display availability. A local removal retry releases captured files only after durable removal succeeds and does not repeat the server mutation. Steering consumes only the captured text revision. Late dictation also requires the original owner and exact text revision, including edits away and back.

TranscriptMessage and TranscriptToolResult normalize copied passive display facts without raw rows or runtime permission. TranscriptReading owns reading and notification focus; NotificationInput is a pure immutable domain value, imported directly by workspace rather than through the coordinator that borrows workspace/registry authorities. Slash completion uses immutable query-bound observations and required captured completion/save callbacks. Workspace owns catalog-versus-argument strategy and capture validation; the pure model owns decoding, Unicode range conversion and exact-query insertion. Cursor, debounce, popup generation and rendering remain in the suggestions widget.

| Current role | Allowed responsibility | Dependency target |
| --- | --- | --- |
| domain | Identity, facts, validation, comparisons and pure projections | Domain and genuinely pure utility |
| data | Scoped transport/storage parsing and repositories | Domain, suitable utility/platform I/O; never a view |
| application | Multi-step commands, revisions, conflict/uncertainty, ordering and business lifetimes | Domain/data/platform/utility; never screens/widgets/routes/text or scroll controllers |
| presentation | UI-facing immutable observations/formatting and intent exposure | Domain and narrow feature command interfaces |
| view | Layout/animation/accessibility/focus/text/scroll/tab state/dialogs/simple routes | Typed feature observations/commands; direct raw HTTP/storage/channels/wire interpretation is migration debt |
| platform | Native channel/resource/lifecycle adapters | Typed domain/platform values; narrow framework glue |
| utility | Purpose-specific helper shared at appropriate boundary | Pure helpers may serve domain; impure utilities are not a loophole |
| composition | Construct/share/release dependencies only | May wire both sides; no existing lib file qualifies for a broad exemption |

Current violations are represented by exact parsed import/library/type locations in `tools/architecture/baseline.json`. The baseline rejects additions and stale entries. Actual parts collapse to their real library; conditional imports/exports count as edges. A green graph or empty baseline proves only its specific properties; it does not prove business ownership, asynchronous behavior or whole-program completion. Use the explicit view inventory for ownership review. See `tools/architecture/README.md` for independent rule commands, fixtures and measured timing/budgets.

The saved connection/OAuth boundary and its structural-versus-behavioral regression ledger live in [the ownership contract](../plans/001-connection-auth-ownership-contract.md). Domain grants are immutable; one preferences/secure-store scoped registry owns refresh/persistence, while consumers receive explicit captured access. [The setup contract](../plans/001-connection-setup-ownership-contract.md) specifies ConnectionSetupSession's required factory, provisional authorization lifetime and stock protocol boundaries. Static guards protect finite properties; held token delivery, exact password bytes, route retirement and final physical sends require controlled behavior evidence.

## Lifetime boundaries to preserve

Connection-retained registry owners outlive routes; route visibility leases determine observation work. Profile repositories capture immutable canonical scope. Editor inputs/confirmation dialogs belong to a route; the edit baseline/revision/write/readback/conflict belongs to the feature. Async completion checks operation generation and original scope/session identity before committing; mounted only proves a widget exists. Notification/share acceptance distinguishes server acknowledgement, local persistence, cleanup and unknown outcomes. Never roll back newer work when an older save fails.

The view acquires/releases injected controllers or route leases and forwards lifecycle visibility. The feature owns retry/poll/backoff/expiry policy and cancellation. ProfileSupervisionSession borrows canonical facts across inline/modal panels; issued criterion reviews/editors and detail windows have separate user lifetimes, tail polling and feedback. No second roster/process/control cache is introduced. Dispatch predicates sit next to physical control RPCs; chat-local /stop captures its actual process owner/runtime before each process.kill offer. Full browser refresh resets arrangement before its final publication; failedOnly recovery retains healthy order. A closed workspace preserves prepared delete receipts and drafts for recovery; known-unsent retirement starts only while its owner is alive.

Workspace intelligence reads capture their resource, durable chat key, runtime,
read generation and intelligence revision. Admission runs before I/O and again
before decoding or publishing its completion. Newer reads, hydration and
configuration writes invalidate old captures even when the chat object remains
the same. The picker observes this owner decision; widget identity checks cannot
protect owner facts after the write has happened.

Voice distinguishes device-wide saved preferences, profile configuration, microphone/playback sessions and preview leases. Existing input/output controllers fence arbitration and completion with captured target/generation. File transfer distinguishes native intake, app-staged copies, server upload and transient delivery resources. HTML retains original source separately from its render budget. PDF native handles remain leased until admitted decoding settles, including after route retirement; original bytes are released after opening. shareRemoteFile releases undispatched staging failures and Wing Android staging after the native adapter copies to its own cache. OwnedRemoteFiles owns scoped application resources; its raw adapter contains transport only. Native callback/string registrations and resource names are runtime roots even without Dart/static callers. These source contracts do not certify native/device behavior or render performance.

## Whole-checkout and runtime roots

`tools/architecture/roots.json` schema 1 is an auditable declaration manifest:

- `scope`: application root, base revision, tracked/intentional-untracked counts and excluded build/cache/installed-dependency trees. The census is explicitly not liveness proof.
- `files`: every scoped file with `path`, `area`, and `provenance` (`tracked` or `intentional-untracked`). Every authored area and checked-in generated/vendor/platform input is included; generated/vendor files are classified resources, not automatically deletion candidates.
- `roots`: `id`, `kind`, `path`, `purpose`, registration `source`, `status` (`supported` or `needs-decision`) and optional `selector` for callback/method/resource names. Roots include lib main, supported alternate mains, all host/device entry points, Android manifest/channel/platform-view/plugin/resource registrations, opt-in scripts/CI and iOS scaffold roots.
- `direct_dependencies`: package kind, concrete import consumers, dynamic evidence and disposition. Direct imports are an inventory aid; plugins/fonts/configuration/build use also supply roots.

Android sources: MainActivity registers cloud/voice/network/clipboard/PDF/media/notification/monitoring/share/launcher/file-delivery channels and the Mermaid native view. BackgroundMonitoringService/MonitoringRuntime own the retained engine; ChatNotifications contains manifest action/dismiss callbacks and layout/resource references; NotificationInteractionSecurity owns action security; VoiceChannel/VoiceCapture/VoicePlayback own microphone/player callbacks; remaining registered channel classes own their specific resources. Manifest provider authorities/file_paths, plugin `ic_stat_wing` string usage and `raw/keep.xml`, Gradle-generated launcher shortcuts and resource density/API/night variants are explicit roots. Diagram JS includes authored app.js/index.html plus vendored Mermaid and license inputs; retain runtime and license closure together.

The checked-in iOS AppDelegate/SceneDelegate/Info.plist/storyboards/project/test roots are real framework registrations. Android-first product scope is insufficient deletion proof: platform support disposition needs an explicit decision. Fastlane contains four store metadata inputs and no Fastfile/Appfile; these are publishing metadata, not executable lanes. Privacy/license/font/icon/pricing sources, icon/notification-board generators and release-history boundary markers are supported resource/tool roots. Four official-source comparison/generator tools have explicit supported opt-in diagnostic purposes and source prerequisites; their current roots are retained.

`plans/001-dead-code-inventory.md` records candidate closures and evidence, retention/deferred decisions and exact recheck/removal gates. All current lib files are transitively imported from lib/main.dart in the preliminary file graph; that does **not** establish member liveness. Removal includes exclusive tests, flags/branches/exports/helper/dependencies/resources, while preserving independent supported entry points. No aliases/shims or archived replacement files are accepted as removal.

## Ongoing maintenance

Keep this map current when responsibilities or interfaces change. The
[maintenance skill](../tools/agent_skills/maintain-feature-architecture/SKILL.md)
defines which records and checks a change needs. Its review asks whether the map
locates the actual owner, callers and relevant regression check. The completed
program's snapshots retain their source bindings; they are historical evidence,
not a requirement to rerun the cleanup for every feature.
